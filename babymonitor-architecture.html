Connection States
CONNECTED Stream live, heartbeat arriving
DEGRADED 1–2 missed heartbeats (3–6s gap)
RECONNECTING 3+ missed — auto retry w/ backoff
FROZEN Frame hash unchanged for 5s
FAILED Max retries hit — user action needed
Auto-Heal Behaviour
DEGRADED Silent — no user alert yet
RECONNECTING Banner: "Reconnecting…" + countdown
FROZEN Alert + force ICE restart
FAILED Full alert + manual reconnect button
Backoff: 3s → 6s → 12s → 30s (max)
Failure → Recovery Timeline
T+0s
Network drops. Camera device loses connection.
T+3s
DEGRADED — Parent misses first heartbeat. Silent.
T+9s
RECONNECTING — 3 missed. Banner shown. Camera starts reconnect attempt #1.
T+12s
Camera rejoins WiFi or falls back to mobile data. ICE renegotiation via signaling server.
T+14s
CONNECTED — Stream restored. Banner dismissed. Health reset.
Tech Stack
App
Flutter
flutter_webrtc for stream. wakelock_plus to keep camera alive. Single codebase Android + iOS.
Streaming
WebRTC
P2P when possible. STUN/TURN via Cloudflare free tier as relay. ~2–4s latency target.
Signaling
Node.js + WebSocket
Tiny server for SDP/ICE handshake only. Deploy free on Fly.io. Stateless after connection.
Health
Heartbeat + FSM
3s ping interval. 5-state machine. Frame hash freeze detection every 5s. Exponential backoff.
Alerts
flutter_local_notifications
In-app banners + push alerts when parent app is backgrounded.
Future / Enterprise
Replace signaling → managed
Swap Node.js for LiveKit or 100ms. Multi-feed, auth, cloud recording. No WebRTC rewrite needed.
